# OAA chronology

Dates are taken from the OAA home page news column
(`https://www.ai.sri.com/~oaa/main.html`) and from `doc/history.txt` inside the
recovered 2.3.2 distribution. Where the two differ, `history.txt` is preferred:
it was written by the developers at release time, the news column was
maintained by hand.

backwards compatibility.

## What changed late, and why it matters to a reconstruction

The 2.3.2A release notes are unusually informative about the system's weak
points, because they are a list of things finally fixed after a decade. A
reconstruction should treat these as *known-hard* areas rather than rediscover
them:

- **Liveness.** Client agents and facilitators only began exchanging regular
  pings in 2.3.2, so that a dead connection is detected promptly and the agent
  library can attempt to reconnect. Before that, dead connections lingered.
- **Reconnection identity.** The ability for an agent to disconnect and later
  reconnect *with the same identity* is a 2.3.2 addition.
- **Goal ID collisions.** Goal IDs are generated by agent library code and,
  before 2.3.2, started from 1, which could cause replies to two different
  solve requests to be intermixed by the facilitator. From 2.3.2 they start
  from a random integer. The protocol-design lesson is that goal identity has
  to be unique per requester across reconnects, and sequential numbering does
  not give that.
- **Message bloat.** Until 2.3.2 the full goal was echoed back inside every
  `ev_solved` reply. The default changed to sending a variable in that
  position, with `return_goal_with_solutions` available to restore the old
  behaviour for legacy agents. This is the one documented wire-format change
  that breaks compatibility in a visible way: the 2.3.1 Monitor will not work
  against a 2.3.2 Facilitator unless that flag is set.
- **Naming and addressing.** The scheme by which agents are named and learn
  each other's names was reworked in 2.3.2; before it, several situations
  produced facilitator failures reporting "Unable to convert address to comm
  channel". Address handling — symbolic name vs. numeric IP vs. `localhost` —
  was a persistent source of fragility.

`localhost` support for the facilitator hostname was, notably, only added in
2.3.2.

## After SRI

OAA's ideas continued through CALO and, by way of Adam Cheyer's later work,
into Siri. The associated patent family — including US 6,851,115 — was
subsequently held and asserted by IPA Technologies, which is why
litigation-quality captures of OAA documentation exist in the USPTO record.
That lineage is context for the project; it says nothing about the software
itself.

- Exact release dates for 2.2.0, 2.2.1, 2.3.0 and 2.3.1 come from the news

- No 1.x release chronology has been recovered yet. The OAA 1 distribution is
  still linked from the site
  (`https://www.ai.sri.com/~oaa/distribution/distribv1/`) and has not been
  retrieved.
